# Office document reading

The `experiment/office-documents` branch adds `.ppt`, `.pptx` and `.docx` alongside PDF. Import, indexing, rendering and manual search happen locally. The file picker and drag-and-drop use the same loader. Office dependencies load only when an Office file opens; PDF keeps its existing PDF.js extraction and rendering path.

PowerPoint uses `@web-ppt/core` to read modern OOXML and native legacy PowerPoint 97–2003 binary files. Slide order, text, tables and embedded graphics feed a static browser preview. Hidden slides remain in source order. Speaker notes are excluded from search and AI evidence because they are not visible slide content. Fonts, advanced graphics, animation builds and media playback are not guaranteed to reproduce PowerPoint; use PDF for exact print layout.

Word uses Mammoth to extract semantic paragraphs, headings, lists, tables and supported embedded raster images. Margin lays these out into bounded reading pages with searchable text and JPEG evidence. Reading-page numbers are generated by this app, not original Word pagination. Word headings provide an outline. Headers, footers, floating object positioning, merged/nested table formatting and some inline styles may differ or be omitted. Unsupported image formats are flagged. This is a reading preview, not a Word editor or exact Office converter. Legacy `.doc` is not supported; save as `.docx` first.

The reader, manual source cards and voice tool results distinguish PDF pages, PowerPoint slides and Word reading pages. Office preview limitations accompany evidence. The existing `numbering: "pdf"` tool argument remains compatible and means the numbered location in the active document; printed book labels remain PDF-only. Replacing/clearing a document discards its index and previews and stops its voice session.

## Import boundaries

- 40 MB compressed file size and at most 1,000 pages/slides.
- ZIP directory preflight: 12,000 entries, 100 MB total expanded size, 25 MB per entry, before decompression by the document libraries.
- Format signature and expected package part checks; encrypted or corrupt files return an actionable error.
- Parsing runs in a dedicated worker, terminated on completion, cancellation, replacement, errors or a 90-second timeout. Word layout yields to the UI periodically and checks cancellation.
- Worker fetch is limited to local blob/data resources. External document resources are not fetched; macros and document scripts are not executed. SVG previews are sanitized and decoded as inert images, never inserted as document HTML.
- Local source images retain the existing 512 KiB cap, bounded pixel dimensions and source-history limits.
- A voice session still sends microphone audio and requested text/images to the selected provider. Local import itself makes no AI call.

## Validation

Browser fixtures cover actual binary `.ppt`, OOXML `.pptx`, and a multi-page `.docx`, including slide order, Unicode, embedded pictures, tables, tail-text retrieval, source location metadata, image pixels after worker disposal, cancelled/replaced imports, invalid signatures and excessive ZIP expansion. Simulated Realtime sessions verify Office text and images reach the provider with slide/reading-page provenance and that replacing Office with PDF stops capture. Existing PDF/voice regression tests run unchanged except for the renamed file-picker/upload labels.

Fixtures are generated from authored content, not user documents. See `tests/fixtures/README.md`.
